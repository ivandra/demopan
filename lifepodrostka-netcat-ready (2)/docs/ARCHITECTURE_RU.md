# Основание повторной интеграции

Исследованы исходные файлы Netcat 7.2.0, SQL-дамп и HTML-макеты. Ошибка предыдущего пакета заключалась в переносе текстовых узлов в универсальные поля и запуске вывода через общий PHP-диспетчер. Это давало неверную модель редактирования, даже если страница внешне была похожа на макет.

## Проверенные механизмы исходного сайта

| Пример в исходном сайте | Что использовано в новой интеграции |
|---|---|
| Компонент 230 «Врачи»: `fio`, `position`, `img`, `bio`, `skills`, `diploms` | Смысловые поля специалиста; фотография FILE, документы MULTIFILE, биография HTML |
| Шаблон 258 для врачей, `Settings.html`: `$ignore_cc=1; $ignore_sub=1;` | Штатные варианты слайдера и команды, работающие с общими записями |
| Компонент 117 «Новости» | Отдельная запись статьи: заголовок, анонс, текст, изображение, дата |
| Компонент 222 с HTML-текстом | Цельный текстовый блок, а не поле на каждую фразу |
| Компоненты 223 и виджет `regions` | Общая таблица регионов и выбор по домену; новый виджет находит таблицу по ключу компонента |
| `nc_browse_level` в макете | Штатная навигация по разделам |
| `AddCond`, `AddTemplate`, `AddActionTemplate` | Проверка и сохранение заявок через `/netcat/add.php` |

В исходном виджете `regions` был жёстко указан `Message198`, хотя региональный компонент в дампе имел другой ID. Новый виджет получает ID из таблицы `Class` по ключу `zhp_regions` и допускает только известные имена полей.

## Хранение и вывод

Базовые компоненты содержат поля. Варианты оформления создаются API `component->create(..., null, parent_id)`. В инфоблоках записываются базовый `Class_ID` и штатный `Class_Template_ID`. Данные хранятся в обычных таблицах `Message<ID>`.

`Class.html` собирается штатным `nc_tpl_parser::main2parts` для `FormPrefix`, `RecordTemplate`, `FormSuffix`. Остальные части — `Settings`, `RecordTemplateFull`, условия и действия форм — записываются как отдельные штатные файлы. ID компонентов и инфоблоков выдаёт Netcat; в публичных шаблонах нет фиксированных ID из исходного дампа.

Шапка, подвал и настройки — обычный файловый макет Netcat. Файл проекта `netcat/modules/default/function.inc.php` содержит только подстановки региональных значений, UTM и форматирование даты. Исходный файл сохраняется для отката. Ядро, `connect_io.php`, `s_list` и маршрутизация CMS не изменяются.

## Сохранение прежних данных

Новые компоненты создаются в отдельном пространстве `zhp_*`. Существующие медицинские таблицы и таблицы `lp_*` не переиспользуются для другого смысла данных. Прежние инфоблоки перемещаются методом `sub_class->move`, который переносит и принадлежность записей. Откат восстанавливает прежние расположения и настройки из снимка. Новые записи сохраняются в закрытом архиве.

Это намеренный выбор в пользу восстановления: физическое удаление ошибочных компонентов вместе с их объектами уничтожило бы возможные заявки и сделанные после установки изменения.

## Формы и защита

Отправка идёт в штатный `/netcat/add.php`. Для анонимных запросов проверяются код сессии, токен формы, контакт, согласие, ограничение длины, поле-ловушка и частота отправки. Ответы квиза проверяются по опубликованным вопросам в Netcat. Уникальный ключ отправки предотвращает повторную запись при повторе запроса. Домен и UTM заполняет сервер.

В предоставленном ядре `nc_token->verify()` требует авторизованного пользователя. Поэтому для анонимных форм дополнительно используется код текущей PHP-сессии; один глобальный токен гостя недостаточен. Это реализовано внутри обычных частей компонента заявок.

Публичная запись разрешена только компоненту заявок. Чтение заявок, изменение объектов и доступ к региональным настройкам требуют административных прав.
