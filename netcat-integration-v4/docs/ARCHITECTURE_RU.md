# Устройство v4

В качестве образца API и файлового устройства изучены исходные макеты
`lifepodr/netcat_template/template/medelta/`, компоненты и SQL Netcat 7.2.0.
Новая разметка взята из `zhizn-podrostka/zhizn-podrostka/`.

В общем макете находятся `head`, мобильная навигация, шапка, подвал и скрипты.
Дочерние «Главная», «Внутренняя», «404», «Заявка отправлена» наследуют
`%Header` и `%Footer`. Дополнительных оболочек `zhp-layout` и `main` нет.
Содержание страниц собирается из инфоблоков. Старые дочерние макеты v3 при
обновлении остаются в БД, но разделы используют актуальные привязки.

Компоненты хранятся как обычные `Class.html` и части Netcat. Установщик
использует `nc_tpl_parser::main2parts()` с корневой папкой компонентов.
Редактор получает форматированные префикс, объект и суффикс. Автоматические
служебные циклы Netcat сохраняются; редактор очищает их штатной функцией.
Поясняющих комментариев в редактируемых частях нет.

Одиночные редактируемые блоки разделены по контейнерам `section` и `wrap`.
Повторяемые карточки находятся в объекте списка. Постоянные общие секции
целиком в префиксе, без полей и записей. Для крупных текстов используются
цельные HTML-поля визуального редактора. Декоративные картинки и подписи
не превращены в отдельные поля. Калькулятор использует исходные jQuery UI
ползунки; их диапазоны задаются настройками инфоблока.

Статьи и специалисты — общие коллекции, варианты вывода — штатные шаблоны
компонентов. Полный вывод наследуется явным `include $nc_parent_field_path`.
Боковые рекомендации статьи и «Другие специалисты» используют те же записи
с исключением текущей. Настройки макетов читаются через
`subdivision->get_template_settings()`.

Псевдоним установщика `zhp_regions` связан с исходным компонентом №223,
инфоблоком №57. Новая региональная таблица не создаётся. Виджет выбирает
регион по домену; проектные шорткоды раскрывают только разрешённые публичные
поля. Недостающие поля добавляются без изменения существующих значений.

Файловые поля заполняются через `files->field_save_file()`, текстовые данные
— через штатную работу с объектами. Обновление сохраняет идентификаторы и
старые записи. Прежние избыточные поля скрываются через `Field.Checked`,
физические столбцы и их содержимое не удаляются. Общие статичные блоки
перестают читать старые записи, которые остаются в базе.

Формы исходной вёрстки используют штатный `/netcat/add.php`: токен Netcat,
сессионный nonce, проверку контактов, ответы опубликованного квиза и защиту
от повторной записи. Обратная связь выводится в технический `output` внутри
существующей формы. Дополнительных диалогов и форм на страницах нет.
Интеграционный `forms.js` связывает исходные кнопки, фильтры и формы с CMS;
исходный `common.js` сохранён. Правила основного CSS не меняются, адреса
Google Fonts заменены локальными копиями тех же шрифтов.

Ядро CMS и файлы исходного проекта не исправляются. Проектные функции,
виджет регионов и конфигурация сайта сохраняются в резервной копии перед
заменой. Данные прежних инфоблоков сохраняются в закрытом архиве. Откат
возвращает исходные привязки сайта; полная резервная копия БД/файлов остаётся
способом побайтного восстановления.

Длинные должности с неразрывным дефисом получают возможность переноса
при выводе (`wbr`), без изменения сохранённого значения и CSS.
В HTML добавлены только технические атрибуты для якорей, фильтров и форм.
